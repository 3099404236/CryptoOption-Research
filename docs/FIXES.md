# 相对原项目回测的逐项修正

原项目的 LEAN 回测把 Deribit 加密期权当成美股期权来跑，存在系统性错误。V2 保留 LEAN 引擎，从数据、引擎配置、策略实现、评估方法四个层面逐项修正。原项目的数据、代码和结果都没有改动，V2 全部放在新目录里。

## 一、逐项修正对照

| 原项目问题 | V2 做法 | 怎么验证 |
|---|---|---|
| BTC/ETH 按美股时段运行，只处理工作日 09:30–16:00，约 70% 的数据被丢弃，周末不交易 | 在算法里用 `MarketHoursDatabase.SetEntry` 注册 7×24、UTC 交易时段 | `DeribitDataCheck`：每天 1,440 根分钟线，周日也一样 |
| UTC 时间被当成纽约时间读，整体错位 4–5 小时 | 数据时区和交易所时区都设为 UTC | `DeribitDataCheck`：7 个时点的价格和 Deribit 官方接口完全一致 |
| 期权按美式建模，LEAN 模拟提前指派（每个策略 39–107 次） | 欧式期权；`NullOptionAssignmentModel` | `verify_v2.py`：指派/行权事件必须为 0 |
| 实物交割成"BTC 股票"并扛过周末；用周五 16:00 价格结算 | 到期日 08:00 UTC 按 Deribit 官方结算价（30 分钟指数均价）现金结算；结算后只有在没有未到期期权时才平掉永续对冲 | `verify_v2.py`：每笔结算价 = 官方结算价下的内在价值；不允许在还有未到期期权时平对冲 |
| 周五平仓单不成交（取消 607 张） | 期权报价持续到 08:00 到期，结算由引擎内的结算单完成 | 结算笔数 = 到期腿数 |
| 手续费按美股盈透模型（7.8 年只收几百到三千美元） | Deribit 费率：期权按标的价值 0.03%（封顶权利金 12.5%），交割 0.015%，永续 0.05%；永续每小时资金费 | `verify_v2.py` 逐笔核对手续费 |
| 合约乘数 100、整数手 | 乘数 1（1 张 = 1 个币），最小 0.1 BTC / 1 ETH | 机制测试 `tests/MechanicsTest` |
| BTC 分钟数据买价 = 卖价 = 成交价（零价差）；ETH 价差是假设的 ±1% | 报价 = 用最新隐含波动率和当前永续价格算出的模型中间价 ± Deribit 实时盘口的报价半价差（按虚实值程度和剩余期限分组，多次快照取中位数，币本位，统一套用到所有年份） | `verify_v2.py`：每笔市价成交价 = 该分钟的卖一价（买入）或买一价（卖出） |
| "现货逐笔"其实是期权成交附带的指数价，97% 的秒是复制前值 | 标的改用真实的 Deribit 永续：分钟线全量；5 天窗口用逐笔成交生成秒级 K 线 | 同上数据核验 |
| 期权价格过时（一天只成交几次的合约价格停留在前一天） | 两次成交之间按"固定行权价波动率"随标的实时重新定价；波动率超过 72 小时没更新的合约不报价 | 构建日志、链文件 |
| 期权链映射表全是占位值（同一个编号、IV 0.65、Delta ±0.5） | 每天生成真实的合约链（含首笔成交时间），策略只能选择当时已经成交过的合约 | `verify_v2.py`：不允许在首笔成交前下单 |
| 下单量不受流动性限制（按 0.1 BTC 的成交价卖出 200 BTC） | 每腿名义金额 = 净值的 25%，并设上限（BTC 25 个、ETH 400 个）；做市单最多吃到真实成交量的 25% | 参数写在算法里 |
| "破翅飞鹰"其实是对称蝶式 | 分成两个策略：CALL_BUTTERFLY（对称）和 BROKEN_WING_BUTTERFLY（上翼跳一档） | 代码 |
| "SABR-Vanna"没有 SABR | 每小时把 β=1 的 SABR 拟合到当前到期的虚值波动率微笑，用 Bartlett 的 SABR Delta 对冲 | 代码 |
| "AS 做市"从不挂单，回补条件永远不成立 | 按 Avellaneda–Stoikov 公式算保留价和最优价差（γ、κ 按市场宽度校准）。报价保存在算法里，每分钟和该分钟的真实 Deribit 成交比对：成交价穿过挂价才算成交，最多吃到真实成交量的 25%。到期前最后 1 小时不报价 | `verify_v2.py`：做市成交必须有真实成交支持 |
| "OFI"没用订单流 | 按 Alexander 等人（JFM 2023）的净买压思路：用 Deribit 主动买卖方向算平值期权的 vega 加权净买量 | 订单流数据文件 |
| "负 Gamma 挤压"没有做市商持仓数据 | 如实改名为 POST_SPIKE_PREMIUM_SELL（价格异动后卖出权利金） | 代码 |
| "平价箱体套利"用过时价格、腿不同时成交 | 转换/逆转套利：用买卖价对比永续，扣除手续费、交割费和预期资金费，两个期权都在 10 分钟内有真实成交才入场，三条腿同时成交并持有到结算 | 代码 |
| HAR-RV 的预测值算出来没用 | 用 7 天直接预测的 HAR 回归（滚动 365 天 OLS），和周度平值 IV 比较决定卖还是买 | 代码 |
| 希腊值用固定 65% 波动率 | 每个合约用自己报价反推的隐含波动率 | 代码 |
| 比例价差没有"4% 熔断" | TREND_RATIO_SPREAD_STOP：价格越过空头行权价 4% 即全部平仓（看跌版向下、看涨版向上） | 代码 |
| 看到 ETH 下跌后才改成看跌结构（事后调参） | 方向由开仓时过去 24 小时涨跌决定，参数事先固定，不在测试窗口上调 | 代码 |
| 5 天回测的夏普没有统计意义；总收益÷回撤被当成 MAR | 周度策略用 7.8 年 BTC 和 6.8 年 ETH 数据；日内策略加跑一年期分钟级；统一用年化收益、超额夏普、最大回撤、Calmar（年化收益÷回撤） | `run_suite.py` |
| 批量脚本用正则改源码、按"最新文件夹"认领结果、硬编码结果 | 用 LEAN 参数传策略；从 LEAN 输出里读取本次结果目录，并核对日志里的策略名 | `run_suite.py` |

## 二、仍然存在的局限

1. **没有真实的历史盘口。** Tardis.dev 的免费样本被 Cloudflare 人机验证挡住（没有尝试绕过）。我也试过两种从成交数据反推历史价差的方法，但都不可靠，没有采用：
   - 成交价对 Deribit 标记价：2021 年以后交易记录里的标记价几乎贴着成交价，估出来接近 0。
   - 60 秒内一买一卖的价差：中位数为 0，因为一张大单会在同一价位拆成很多笔。

   所以价差用的是 2026 年 10 月多次抓取的实时盘口（币本位），统一套用到所有年份。2019–2021 年盘口更薄，早年成本被低估（对策略有利）。另外提供 0、0.5、2 倍价差的敏感性结果。
2. **报价是模型报价。** 两次成交之间沿用最近一次标记价反推的隐含波动率（固定行权价）。波动率微笑在两次成交之间的变化无法观测。
3. **做市成交假设**：只要真实成交价穿过挂价就算成交，不模拟排队顺序，偏乐观。
4. **永续对冲**：按 0.05% 吃单费和每小时真实资金费计。资金费记录从 2019-04-30 开始，之前按 0 计。另有一组对冲免手续费的对照。
5. **保证金**：用的是 LEAN 的期权保证金模型，不是 Deribit 的组合保证金。按美元记账，相当于 USDC 线性期权；币本位（反向）期权的币价敞口没有建模。
6. **闲置现金**：不计利息。比较时请对照短期国债收益率（夏普已扣除无风险利率）。
